# Stage-1 execution log (`cathedral_stage1_execution_log_v1`)

Stage 1 runs a miner's committed harness on a fresh sealed batch and, until now, kept only the
exploit bytes. We were executing the agent and throwing the execution away. This log retains that
trajectory as a **by-product of grading** — no new incentive, no miner-supplied trace, nothing to
trust (distill#142). The control-plane companion that receives, stores and verifies it is
cathedral-cybergym-backend#3.

## It is an execution RECORD, not a reasoning narrative

The log records **what the harness did and saw**, never what it "thought". Each step carries:

- `action` + `args` — the tool call the harness made
- `result` — the observation: `stdout`, `stderr`, `exit_code`
- `files` — file effects as `{path, op, sha256}`
- `ts_ms` — a relative timestamp

There is **deliberately no free-text thought/reasoning field**. That field is exactly what made
padding gameable in the miner-submitted trace path (`trace_submission.py` only checks sentence
repeats *within* a step). This log is graded execution we ran ourselves under a committed harness
digest, so its trustworthiness comes from the run, not from a claim. `build_execution_log` drops
unknown step keys, so a runner cannot smuggle a narrative field back in.

## Shape

```jsonc
{
  "schema": "cathedral_stage1_execution_log_v1",
  "task_id": "arvo:900001",
  "task_family": "arvo",              // id prefix, so a corpus can group by domain (#143)
  "model": "deepseek-v4-pro",         // the miner's registration-signed model (backend provenance); "" until supplied
  "terminal_reason": "no_output",     // solved | no_output | timeout | crash
  "duration_ms": 4213,
  "steps": [
    {"seq": 0, "action": "run_harness", "args": {"argv": ["..."]},
     "result": {"stdout": "...", "stderr": "...", "exit_code": 0},
     "files": [{"path": "<stdin:challenge_artifact>", "op": "read", "sha256": "sha256:..."}],
     "ts_ms": 4213}
  ]
}
```

Serialisation is sorted-key compact ASCII JSON, so the bytes are **content-addressable**: the
sha256 is the `HarnessResult.log_sha256` reference, keeping `HarnessScore` small and comparable.

## Persisted for every dispatched task — failures included

`evaluate_harness(..., log_sink=...)` calls the sink **before** the solve/no-solve branch, once per
**dispatched** task. A harness that produced nothing is stored exactly like one that solved. Failures
are the corpus rows most likely to be silently dropped and, for skill distillation (#143), the most
useful — win/loss contrasts and failure-mode frequencies cannot be computed from wins alone. The
backend persists via `AgentStore.store_log` into a sibling `logs/` tree with round-window retention
that does **not** evict by harness rank.

`local_harness_runner` emits this exact shape, so the dev/test path and the production enclave runner
produce identical logs.

## Enclave egress (decided; implementation lands with the enclave runner)

The production runner executes inside a TDX enclave with **no network egress**, so the log cannot be
POSTed out from inside the run. The decision:

1. The enclave runner writes the `cathedral_stage1_execution_log_v1` bytes as a run **output artifact**
   (the same channel as the exploit), and includes `log_sha256` in the signed result envelope so the
   log is **bound into the attestation** and cannot be edited after the fact — the same result-binding
   the receipt already uses for the exploit.
2. The control plane recomputes `sha256(log)` on receipt and checks it against the attested
   `log_sha256` before `store_log`; a mismatch is a rejected log, not a silent overwrite.

The runner-contract, format, local runner and storage land now (this change); the enclave runner
emitting the artifact + the `log_sha256` attestation binding land with the enclave runner itself, as
distill#142 allows.

## Open items settled here vs. deferred

- **Size** — per **task** cap (`MAX_LOG_BYTES`, 8 MB), not per round; truncate-and-mark on overflow.
- **Retention** — `prune_logs` keeps whole rounds in a window, all miners/tasks, so failures survive.
- **Licence** — the reuse terms for a log generated by running a miner's committed harness are set at
  **registration** (with the harness commitment), not at submission. Wiring the licence field through
  registration is a follow-up; it does not change this format.
