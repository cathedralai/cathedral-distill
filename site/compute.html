Why not just another sandbox

E2B and Daytona isolate. Cathedral isolates and attests.

Generic sandboxes answer "did the process run?" Cathedral answers "did it run inside the measured environment we promised, with this exact workload bound into the receipt?" That is the wedge for agents handling secrets, regulated data, or work that has to be replayed by a third party.

The difference

Verified ≠ confidential

Core-style rented GPU paths guarantee correctness of results, not privacy from the GPU host. Secure Sandbox (TDX CVM + optional CC-GPU) extends trust to the worker. We say which profile you are on; the receipt says what we proved.

attest.v1

One-shot jobs

Fresh TDX environment, bounded runtime, no egress, result-bound receipt, confirmed teardown. Pay only when execution completes.

custom.v1

Persistent workers

SSH into a sealed CVM. Docker inside the guest. Hourly metering after the workload is ready. You verify the quote before the first keystroke.

API flow

Three calls to a verifiable result.

Create a scoped API key

Dashboard at cathedral.computer. Google or email link. Keys are shown once; we store only a SHA-256 hash.

POST /v1/workers

Pick a profile, set budget and lifetime, pass an idempotency key. Response is 202 with a worker ID.

Poll, then keep the receipt

GET /v1/workers/{id} until terminal. Download /v1/receipts/{id}. Verify offline with cathedral customer-receipt verify.
