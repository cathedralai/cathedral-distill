The technical case

A benchmark that can't be trained on.

For security researchers and ML people: why execution beats judgement, how commit-then-challenge sealing defeats contamination, and why a verified PoC + trace corpus is the asset worth building.

The problem

Every public benchmark decays the moment it's public.

A score measures capability only until the test set leaks into training. For coding and security, that half-life is short: the benchmark is scraped, distilled, and memorised, and the number stops tracking the skill. You cannot fix this with a bigger held-out set — only with a set that provably did not exist when the model was trained.

Verification, formally
solved ⟺ exit(vuln, poc) ∉ {0, 300} ∧ exit(patch, poc) ∈ {0, 300}

The PoC must crash the sanitiser-instrumented vulnerable build and leave the patched build clean. This isolates the specific vulnerability the patch fixed from any incidental crash — no LLM judge, no rubric, no partial credit. The verdict is a subprocess exit code.

Anti-contamination

Commit-then-challenge sealing.

The guarantee isn't "we held out a set." It's an ordering enforced against the chain: the model is fingerprinted before the questions are drawn, so the questions can't be in the model.

1 · Anchor the nonce after commitment

The batch-draw nonce is derived under a domain separator from a finalized block + hash, the audience, the epoch, the miner, and the digest of the model committed before that block. Every validator reproduces the identical nonce; none can steer it.

2 · Draw from a post-cutoff holdout

Tasks are selected only from vulnerabilities disclosed after the cutoff the committed model predates, ranked by a nonce-keyed hash. Same pool + nonce → same batch. An exhausted holdout refuses rather than recycles.

3 · Re-derive, never trust

Work units are a pure function of the committed task. The validator recomputes every number — earned = Σ per_level_solved × level_weights — from a signed receipt; a worker's reported score is never counted.

4 · Paired evaluation

A challenger is compared only to the incumbent re-scored on the same batch. Variance in which vulns each drew cancels out; the crown turns on capability, not luck of the draw.

Implemented in cybergym_batch.py, cybergym.py, frontier.py; the derivation and re-scoring paths are covered by the test suite.

The dataset thesis

The exploits aren't the product. The verified corpus is.

Each solved task can carry a reasoning trace — the agent's steps, file:line references, and the PoC it wrote. Verified, licensed, and sealed, that trace is written to the corpus verbatim: the submission format is the dataset format, so a verified solution compounds into training data with no transformation.

Execution-labeled

Every row is attached to a crash the validator re-ran. No noisy heuristic labels, no self-report — the ground truth is a binary exit code.

Contamination-dated

Rows come from post-commit disclosures, so a model trained on the corpus is trained on data provably outside its own frozen predecessor's reach.

Quality-floored & licensed

A structural, model-free gate (≥5 steps, read+write actions, ≥200 reasoning tokens, ≥2 file:line refs, no padded loops) plus an explicit reuse licence. Padded or unlicensed traces never enter.

NoteThe trace contract, quality floor, and corpus writer are built and tested (trace_submission.py, cybergym_service.py). The corpus store at scale and curation are integration work.
